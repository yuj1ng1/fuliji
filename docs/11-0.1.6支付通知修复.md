# 福理集 0.1.6：支付通知识别与连接恢复

## 问题与证据

旧版只按部分支付标题和交易词过滤通知，支付宝“交易提醒”标题及“支出”语句会被忽略。界面还可能停留在“已授权、等待连接”，缺少恢复入口，也不能判断是否收到、过滤或保存失败。

代码已确认标题和交易词规则的缺口。手机截图中的等待连接状态并不能确定系统断连的具体原因；本轮没有把低电量、系统限制等猜测当作已定位根因。

## 行为变化

- 支付宝来源新增“交易提醒”标题和支出识别；微信标题规则独立保留，普通聊天和其他应用不作为支付来源。
- 明确的“你／您有一笔…元的支出”语句可排除后面的促销金额；例如合成通知“你有一笔18.60元的支出，点击领3元合成优惠券。”识别为 18.60 元候选。不会从任意多金额通知中取第一个或最大金额；多个实际支出语句仍要求核对金额。
- 读取标准正文、展开正文及列表式正文，空展开正文可回退。片段中的失败或待付款状态会否决候选；金额冲突不自动选一个，交易类型冲突不保存。汇总通知本身不记账。
- 进入应用时，在用户已经授权的前提下尝试恢复监听；提供“连接并检查现有通知”按钮。自动恢复请求间隔至少 60 秒，手动请求间隔至少 2 秒，不循环改变系统设置。
- 只在系统实际连接回调后检查现有通知；手动再次检查沿用当前连接。连接状态不从磁盘恢复为“已连接”。
- 显示最近支付来源、收到时间、处理原因及现有通知检查时间和数量，区分空正文、规则未匹配、失败交易、重复和写入失败。诊断只保存固定来源、原因代码、时间与计数；不保存通知标题、正文、商户、通知键或原始异常。
- 新增“核对待确认支付”快捷入口。金额识别成功仍先保存为 DRAFT，核对后保存为支出，才增加首页、月支出和消费曲线。完全相同事件不重复插入，也不覆盖已确认账目。

Android 官方说明 `getActiveNotifications()` 面向当前可见通知，需等待连接回调；`requestRebind()` 依赖本人已有授权。因此检查现有通知无法恢复已清除记录，也不是历史账单接口。参见 [NotificationListenerService 官方文档](https://developer.android.com/reference/android/service/notification/NotificationListenerService)。

没有新增通知发送权限、无障碍权限或前台常驻服务，也没有自动修改通知授权、系统过滤器或省电策略。通知访问和发送通知是不同能力。没有更改学校登录、宿舍更新及已有账本统计口径。

## 复现与验证边界

常规设备测试不需要支付软件、学校账号或真实消费。可信支付载荷直接交给生产使用的 `NotificationPaymentReader` 和 `PaymentNotificationCapture`，使用 Android `Notification` / `StatusBarNotification` 对象以及 Room 数据库；不是仅手写最终候选。失败写入使用隔离数据库触发器，验证错误反馈。

系统探针在自有 API 35 模拟器上单独执行：临时允许本应用通知监听，接收由 Android shell 发出的真实系统通知，验证连接回调、断开后重连、现有通知读取和手动检查。shell 来源不会通过微信／支付宝过滤，也不会进入账本。测试不安装冒充支付宝的应用；合成支付内容读取与真实系统回调属于两个独立验证层，尚未验证两者在用户手机上的实际连通。

## 更新后使用

覆盖安装后进入账本，检查“支付通知”状态；已有授权时可点“连接并检查现有通知”。仍未连接时，可在系统授权页由本人关闭后重新开启，再返回查看。保留在通知栏中的通知才可能补读；已清除记录请手动补记。

识别后点击“核对待确认支付”，核对金额、类型和日期来源后保存为支出。没有候选时先查看最近处理结果；没有支付来源回调和收到但未识别是不同问题。不要为了验证专门付款。
