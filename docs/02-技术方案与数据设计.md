# 技术方案与数据设计

版本：开发前草案 v1.0；日期：2026-10-30。本文是实现建议，不是已通过的技术验证报告。

## 1. 技术选择

| 部分 | 建议 | 选择依据及边界 |
| --- | --- | --- |
| 应用 | 原生 Kotlin + Jetpack Compose | 首版只面向安卓；通知监听、提醒、WebView 和本地存储直接使用平台能力；Compose 为 Android 官方推荐 UI 工具包 |
| 系统基线 | 目标 Android 16 / API 36；建议 minSdk 31 | 真实验收设备为用户的 Android 16；较旧系统兼容是工程建议，不承诺未经测试的其他设备 |
| 数据 | Room + DataStore | Room 保存课表、考试、成绩、电量和账本；DataStore 保存偏好，不承担关系型数据或明文凭据存储 |
| 学校登录 | 应用内受限 WebView，M0 验证后定稿 | 本人完成原学校认证；不假定能继承桌面、系统浏览器或企业微信登录 |
| 数据同步 | 按来源独立的读取组件 | 先核实实际请求；不能先按常见教务产品猜测私有 API |
| 后台更新 | WorkManager，仅用于已验证可后台执行的读取 | 周期任务不是准点任务；不用于课程或考试的准时提醒 |
| 课程/考试提醒 | AlarmManager + 本地通知 | 精确提醒单独处理用户授权、重启及数据变化后的重建 |
| 记账采集 | NotificationListenerService | 用户主动启用的系统通知访问；与发送通知的权限不同 |
| 服务端 | 首版无自建后端 | 手机直连学校，业务数据主要在本机；避免额外账户和运维 |

采用一个应用模块，内部按功能组织；共享会话、数据库和调度基础设施。先不引入多工程、微服务、AI 模型或复杂依赖注入框架。

依赖版本在创建工程时核对官方稳定版本和 Kotlin、Gradle、AGP、JDK 的兼容组合并固定；本文不把文档示例版本当作已验证构建环境。

## 2. 数据流与模块职责

学校页面/已验证读取请求 → 来源读取组件 → 数据校验与标准化 → 本地数据库 → 页面与提醒。

支付通知 → 来源筛选 → 类型/字段识别 → 重复与歧义处理 → 自动入账或待确认 → 本地数据库 → 账本统计。

| 组件 | 单一职责 |
| --- | --- |
| 连接管理 | 教务和后勤分别维护连接状态；不把一处登录成功扩展为所有来源可用 |
| 教务读取 | 课表、考试、成绩；保留各自查询条件、完整性和结果状态 |
| 后勤读取 | 房间选择与电量查询；校验返回结果属于当前房间 |
| 校历读取 | 已核实的学校公开文章及原版附件；管理学年、来源与文件版本 |
| 账本识别 | 微信/支付宝通知规则、分类、待确认与重复处理 |
| 数据仓储 | 原始标准化快照、用户修正、历史与查询状态的本地一致性 |
| 提醒调度 | 仅根据有效业务数据安排、更新和取消本地提醒 |

## 3. 学校接入策略

### 教务

首版优先验证用户已使用的 WebVPN 路径，校内直连作为后续优化。入口列表及证据见核验记录，入口地址不是数据 API。

本人登录 → 进入目标查询页面 → 选择学年学期 → 完成查询 → 读取已验证请求的结果，或在前台读取已渲染页面中的限定业务字段 → 校验完整性后保存。

优先使用已核实且登录规则允许的读取请求；如果只能读取页面，则明确前台同步边界。不能在后台长期维持隐藏页面来冒充可靠后台同步。

需要在 M0 核实：请求参数、响应结构、分页/全部记录、服务端选择条件、重定向、会话有效期、WebVPN 地址转换、浏览器与 HTTP 客户端之间的会话可用性。不能默认把 Cookie 拷贝给 HTTP 客户端就会成功。

登录页、验证码页和业务结果必须通过目标页面及结构信号区分。HTTP 200、页面标题正常或跳转结束都不足以判定同步成功。认证要求改变时回到本人登录，不自动试密码或处理验证码。

### 后勤

单独核实完整登录路径，不把后勤直接访问地址与教务 WebVPN 认证合并推测。已知页面有房间选择字段和剩余电量字段，但数值可能需要选房间后才加载。

明确区分只读查询、本地选房间、远端修改绑定和充值四类动作。首版读取层只实现必要且已经确认语义的操作；充值按钮不参与同步。

每次读取同时核对房间身份、单位和数值。页面上存在电量输入框但没有值时返回缺失状态；不能转成 0 或沿用其他房间结果。

新增日用量接入：桌面实查“房间用量”页的 #picker-addr-view 与 #tab4 ul.table，每行提供日期和原始用量数值。M0 将余额和用量保存为独立来源快照，均按房间隔离；只有同房间数据才能合并展示。近 7 天按上海时间的完整自然日生成，缺失值保留 null，绘图只连接相邻有效点，不由余额差计算用量。原表未注明用量单位，界面明确保留这个来源限制。

### 校历

优先使用已核实的教务处公开校历文章，不要求连接教务账号。文章嵌入官方 PDF；本学年原件已取得并经全文提取和整页视觉核对。原版查看与离线保存是首版能力，自动日期提取不是前置承诺。

按学年保存文章来源、原件校验值、获取时间和经过人工核对的周次配置。新学年的官方链接可以人工维护；不依赖猜测网址或让模型生成日期。

本学年已核对的起点见来源记录。尤其 2027 年春季正式上课日为 2 月 23 日，而第 1 周周一是 2 月 22 日；学期起止、正式上课日、教学周锚点分别保存，不用同一个日期代替。

### 网页边界

只允许已核实的 HTTPS 学校主机进入受限登录/业务浏览区；外部链接交系统浏览器，新认证主机先核实再加入范围。证书错误不绕过。

网页读取不得注入能访问账本、任意文件、密码或任意网络目标的通用原生桥。需要脚本读取时仅提取限定业务 DOM 字段；不读取密码框，不记录登录表单内容。页面不提供调用本地账本的能力。

## 4. 查询与缓存状态

以下是应用内部设计状态，不冒充学校接口字段。

| 维度 | 建议状态/字段 | 用途 |
| --- | --- | --- |
| 最近尝试 | 未开始、进行中、成功、需登录、网络失败、格式无法识别 | 保留本次失败原因，不覆盖上次成功时间 |
| 本次完整性 | 完整、部分、未知 | 防止部分页面或第一页冒充完整列表 |
| 已保存结果 | 有记录、已确认空结果、无有效快照 | 区分从未同步与本次明确查询为空 |
| 新鲜程度 | 按刷新规则计算；同时显示最后成功查询时间 | “本次刷新失败，显示此前数据”可以同时成立 |
| 来源时间 | 来源明确提供时保存，否则未知 | 获取时间不是业务更新时间 |
| 查询身份 | 来源、账号本地标识、学年学期或房间、筛选条件 | 防止跨学期、跨账号、跨房间混用 |

只有查询条件正确、分页完整、结果结构明确时，空列表才作为确认空结果保存。部分解析、登录失效或网络错误不清空有效快照。

同步按来源与查询身份去重并发。认证失效或格式变化停止自动重试，保留数据并显示对应入口；网络失败允许有限退避，不能不断刷新学校页面。

## 5. 核心数据

| 数据 | 必要信息 | 规则 |
| --- | --- | --- |
| 学期 | 学年、学期、已核对的第 1 周周一、时区、节次配置 | 时区固定 Asia/Shanghai；周次起点不由报到日直接推断 |
| 课程 | 来源身份、课程标识/名称、教学班、星期、节次集合、周次集合、地点、教师、原始周次表达 | 允许部分字段缺失；无法解释的规则需复核，不能生成确定提醒 |
| 实践/其他课程 | 名称、周次、原始说明、无固定节次标记 | 独立展示，不编造具体上课时刻 |
| 课程修正 | 对应源记录、覆盖字段、适用日期/周次、修改时间 | 与源快照分离；同步冲突提示本人处理 |
| 考试 | 学年学期、源标识、课程、原始时间、可确认的起止时间、地点、校区、座号、考试性质 | 解析不明的时间保留原文，不安排猜测提醒 |
| 成绩 | 学年学期、源标识、课程、原始成绩、学分、来源绩点、成绩性质与备注 | 同课程补考/重修保持区分；不自行判定覆盖关系 |
| 校历 | 学年、官方文章链接、原件副本、获取时间、校验值、人工核对配置 | 变更原件不静默覆盖已经确认的教学周设置 |
| 电量快照 | 房间标识/展示名、电量十进制值、原始单位、查询时间、来源时间（可空） | 空白/非有限数无效；来源明确给出负值时保留语义，不擅自截成 0 |
| 日用量快照 | 房间展示名、逐日日期、来源十进制数值、保存时间、单位确认状态 | 日期有效且不重复，数值非负；缺失不补 0，不跨房间拼接，不将原站未标明的单位当作已确认 |
| 通知证据 | 来源应用、通知键与发布时间、内容指纹、最小支付字段、识别规则版本 | 只持久化已识别或需要确认的支付证据，不保存无关聊天通知 |
| 账本记录 | 稳定本地 ID、来源交易 ID（可空）、方向/类型、金额分、币种、时间及时间依据、商户/分类、确认状态、关联原记录 | 用户修改独立保留；通知时间不伪装成来源已证实的交易时间 |
| 同步记录 | 模块、查询身份、最近尝试状态、完整性、最后尝试/成功时间、可展示错误 | 日志不包含账号密码、Cookie 或完整敏感响应 |

列表以来源稳定标识优先关联。没有稳定标识时使用经过核实的组合字段；有歧义不自动合并。更新以完整查询快照为单位，其他学期数据不被当前学期刷新删除。

## 6. 课表解析的确定规则

优先读取经过核验的结构化结果；只有不得已时才解析页面文本。标准化后的周次必须能回溯原始表达。

- 逗号连接的各段取并集，区间包含首尾。
- 单/双限制只作用于所属段，不能把整条表达式统一过滤。
- 现场出现的 1周,5-7周(单),8-10周(双),11-15周，应得到 {1,5,7,8,10,11,12,13,14,15}。
- 同一格存在不同周次的多条课程时分别保留，不只读取第一门。
- 连堂可跨多个节次，实践课程和无固定节次课程保留为独立类型。
- 原课表已体现的调课不再自动应用校历调休。人工调课覆盖有明确适用日期，源更新后需要核对冲突。

## 7. 自动记账规则

处理顺序：来源应用筛选 → 去除汇总类通知 → 识别交易状态与方向 → 解析单笔金额 → 识别时间依据 → 检查重复 → 自动入账或待确认。

自动入账须同时满足：明确的已完成支出、单笔金额和币种无歧义、时间依据可解释、无已知重复、规则已通过对应来源样本验证。不能只因出现“元”或一个金额就记为消费。

来源交易 ID 是强重复依据。通知键可能被支付应用复用；金额、商户和分钟也不足以证明同一交易。对重复回调、同键内容更新、两笔同额交易分别测试；缺乏确定依据时进入待确认，不静默丢弃可能的真实交易。

退款和原消费以独立记录关联；部分退款不覆盖原金额。无法关联时待确认。转账和充值的消费归属可由本人修正。

通知中的真实交易时间优先；只有系统通知发布时间时记录为“通知时间”。延迟到达的消息不能默认等于现在发生的交易。统计按可解释的记账时间展示，未知时允许本人修改。

不使用无障碍读取支付界面，不读取支付应用私有数据库，不绕过系统隐藏敏感内容的限制。Android 15 及以后对部分敏感通知有内容隐藏，不能据“通知栏可见”推断监听器一定收到完整内容。

## 8. 提醒、后台与 Android 16

发送应用通知、访问其他应用通知、精确闹钟是不同授权，分别检测与引导。权限缺失有明确状态；普通查看和手动记账继续可用。

WorkManager 周期任务最短周期为 15 分钟，但执行可因系统约束延后；Android 16 也调整了任务配额。约每 6 小时电量刷新是可选调度目标，不是服务承诺。

课程/考试使用本地时间提醒；精确提醒根据需要请求 SCHEDULE_EXACT_ALARM，并在每次安排前检查。未授权时明确提示提醒可能延迟，不用周期任务伪装成准时提醒。

应用启动、时间/时区变化、设备重启后首次解锁、权限变化和课程/考试更新后，按有效本地数据重建提醒。失效、取消或变更事件对应的旧提醒必须撤销。

OriginOS 6 真机分别检验前台、普通切后台、锁屏、重启和用户强制停止。系统禁止运行时不保证补收全部历史通知，不要求绕过系统限制。

## 9. 本地数据与导出

应用私有存储保存业务数据；不引入广告、分析或云同步 SDK。密码由本人输入学校页面，应用不另存密码或集中上传会话。

WebView 自管会话不随意复制；确需由应用持久化的秘密使用 Keystore 管理的密钥保护。Room、DataStore 或“应用私有目录”本身不等于数据已经逐项加密。

明确配置系统备份范围：学校会话、支付通知证据和账本不进入默认云备份；用户主动导出单独处理。验证排除规则，不以“没有自建服务器”推断绝无系统备份。

账本自有 CSV 包含格式版本、记录 ID、金额分、类型、时间及时间依据、分类等字段；导入校验版本、必填项与金额，保留现有记录，文本列避免被表格软件执行为公式。学校凭据、会话和原始通知正文不导出。

校园缓存与账本分开清理。换学校账号时隔离先前校园数据；退出登录不误删独立账本。数据结构升级必须迁移，不以重建数据库清空账本。

## 10. 方案尚未获得的证据

仍未完成指定手机上的学校登录与同步、实际支付通知样本、节次时间和准点提醒验证。桌面已核实课表、余额和每日用量的结构及非空结果；本地构建、规则/模拟器结果、当前离线校历实现详见 M0 使用与验证记录。桌面检查和模拟器不能代替 iQOO / Android 16 真机验证。
