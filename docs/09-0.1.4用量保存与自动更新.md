# 0.1.4 用量保存与自动更新

日期：2026-10-31，北京时间。福理集 0.1.4-m0，versionCode 5。

本文保留为历史记录。后续首页、节次时间与账本统计见[0.1.5 记录](10-0.1.5首页双版与账本统计.md)。

## 用量表有数据，保存却灰色

用户真机反馈已能保存余额；学校“房间用量”也显示日期和数值，但应用标题仍是“宿舍电量”，保存按钮灰色。代码确认旧版把读取类型固定为进入页面时的来源。从余额入口切到用量标签后，仍去检查被隐藏的余额字段，因此把有结果的页面误判为尚未查询。

本次按当前可见标签确定 POWER 或 POWER_USAGE，同步更新标题、校验与保存类型，两个入口均可切换读取。用量优先逐行读取学校的 `.table_1` 日期列及 `.table_2` 数值列，减少渲染空白字符的影响；加载中、选房中、隐藏表格或不完整行不保存。失败保留已有快照。

本机通过已授权桌面会话核对：用量地址是 textarea；日期与数值分列；日用量由学校选房回调加载。没有将真实账号、房间、数值、Cookie 或签名链接写入测试和文档。

## 每日更新如何执行

宿舍页面新增默认开启的“每日自动更新”，与教务自动更新分别控制；可随时关闭，也可手动点“立即更新余额和用量”。

沿用最近一次保存的宿舍，同时更新余额和日用量，即使原先只保存过余额，也会尝试补齐用量。手动更新当前选择的宿舍时，两组数据使用同一房间。每次从当前已认证页面的房间目录精确匹配完整校区、楼栋和房间名称，再调用学校原有选房完成回调执行只读查询。不猜房间 ID；零个或多个匹配时停止并保留旧数据。没有调用充值、支付、短信或绑定按钮。

后台复用唯一的 WorkManager 任务，约每 6 小时检查一次；回到应用时检查，持续打开时也定期检查是否需要补更。前台尝试间隔和已保存数据的新鲜度均有 30 分钟限制，防止重复请求。取消此前“电池不能过低”的额外约束，仅要求网络连接，但系统省电、强行停止应用和学校会话仍可能阻止或延后更新。不是每天固定时刻执行的保证；Android 官方也说明周期任务的实际时间取决于约束与系统优化，见[周期任务说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work#schedule_periodic_work)。

学校会话及本人选择保存的后勤入口在本应用内复用；要求手机号验证或额外认证时停止自动操作，显示失败原因，保留上次成功时间和图表。重新完成认证后可再次更新，不承诺永久免登录。

图表仍表示截至昨天的 7 个完整自然日；学校未公布的日期保持缺失，不补 0。已知的 0 用量保留；同一房间的历史按日期合并，跨月不丢已保存记录，其他房间的数据不混用。

## 实测和边界

| 项目 | 结果 |
| --- | --- |
| JVM 规则测试 | 39 项通过 |
| API 35 设备完整测试 | 38 项通过；包含新增保存、自动查询和调度案例 |
| 实际应用窗口读取保存 | 合成学校页面：从余额入口保存用量、从用量入口保存余额，均验证按钮可点击、页面完成关闭和数据库保存类型正确 |
| 自动查询到持久化 | 实际 SchoolAutoSync → SchoolSyncEngine → WebView → 打包的 query.js / capture.js → 数据库；学校页面和响应为合成数据，验证自动选房及余额、日用量两个请求 |
| 跨日过期补更 | 模拟旧快照时间，验证两组数据重查；新鲜快照不重复查询，不代表已进行 24 小时持续观察 |
| 错房与关闭开关 | 找不到原宿舍时不查询其他房间、不替换余额；关闭用电更新后，即使教务更新开启也不请求用电 |
| 定期任务 | 单独开启用电自动更新可创建唯一任务；重复配置不增加任务，关闭两类更新后取消任务 |
| Lint | 0 错误、13 项警告，保留依赖更新及 Kotlin 扩展建议 |
| 覆盖安装 | 0.1.3 → 0.1.4 合成账本记录保留；同包名、同签名，APK SHA-256 与最终构建一致 |
| 实际学校与真机 | 已核对真实页面及查询回调；新版真实手机保存、无人选房自动更新、OriginOS 6 / Android 16 后台持续运行尚待用户验收 |

模拟器测试不使用真实账号或学校业务结果，也不把手写 JSON 单元测试当作真实学校读取成功。
