# 需求与页面流程

版本：需求 v1.3；日期：2026-10-31。本文仍含后续完整首版规划，最新周课表、手机后勤绑定及实测结果见[0.1.2 记录](07-0.1.2周课表与后勤连接.md)。

新增确认：减少重复登录，允许自选在手机加密保存学校账号；会话有效期由学校决定。用户已补充独立后勤账号，确认成功使用的是“手机号验证／立即绑定”页面。后勤账号与教务分开保存，短信接收和绑定确认由本人在学校页面完成。

## 1. 已确认与建议的边界

已确认的用户需求：福建理工大学；iQOO Neo9 / OriginOS 6 / Android 16；个人使用；安卓安装包；主要在手机保存数据；本人完成学校登录；课表、电量、考试、成绩、每学年校历及微信/支付宝消费记录。新增明确要求：浅灰白底、蓝色点缀、信息紧凑；电量以余额和近 7 天用量折线图展示。

以下页面组织、刷新周期、提醒提前量和首版细节是为减少开发歧义提出的默认设计，可在开发前评审时调整。它们不是学校规定，也不是已经完成的功能。

| F02 | 课表 | 按学年学期同步；今日与周视图；完整周次与节次；离线查看；手动修正；课程提醒 |

## 3. 页面组织

底部四个入口：今日、课表、校园、账本。设置入口放在首页右上角。

| 页面 | 主要内容 | 可执行操作 |
| --- | --- | --- |
| 今日 | 当前学期/教学周；课程、考试、电量、已记录支出卡片 | 查看详情；刷新对应卡片；进入设置 |
| 课表 | 周切换、七天课程格、实践与无固定节次课程区 | 切换学期；同步；查看课程；手动修正 |
| 校园 | 考试、成绩、校历、电量四个功能入口 | 进入独立详情页；查看各自连接状态 |
| 考试详情 | 已公布考试列表、缺失字段、查询条件 | 刷新；提醒开关；查看原页面 |
| 成绩详情 | 学期筛选、成绩列表、课程详情 | 刷新；查看原页面 |
| 校历详情 | 学年列表、官方 PDF/原图、来源与保存时间 | 获取/保存；查看原文；设置教学周起点 |
| 电量详情 | 当前房间、剩余电量、近 7 天每日用量折线图与明细、查询时间、提醒阈值 | 选房间；查询余额/用量；查看某日数值；开启提醒；打开学校页面 |
| 账本 | 日/月汇总、交易列表、待确认数量 | 新增；修改；筛选；确认记录；导出 |
| 设置 | 学校登录、授权、节次与周次、提醒、数据管理 | 按需配置；清理校园缓存或账本分别操作 |

不把后台服务、解析器、数据接口等实现名词显示给日常使用者。

视觉采用清爽工具型：浅灰白底、蓝色作为操作和选中状态，减少大幅宣传文案与粗边框。首页依次展示日期/校历周、课表、用电图表与余额、支出、校园快捷入口；字体和间距优先保障手机上的信息密度与可读性。

## 4. 关键流程

### 首次使用

打开应用 → 进入可使用的本地首页 → 按需连接教务或后勤 → 本人在学校页面登录 → 返回模块同步 → 预览数据及当前学期 → 确认教学周与节次 → 可选开启提醒。

记账通知访问单独启用；拒绝任何授权仍可查看已保存信息、使用手动账本。首次启动不集中索取所有权限。

### 日常查询与登录失效

打开模块 → 立即显示已有数据和最后成功查询时间 → 满足刷新条件时请求更新 → 成功后显示新数据；需要登录时显示连接入口，保留并标记已有数据。

返回了登录页面，即使页面可以正常打开，也不算获取业务数据成功。每个来源独立显示状态。

### 电量与换宿舍

连接后勤 → 选择房间 → 核对房间 → 查询 → 展示剩余电量及查询时间。切换房间后先显示“尚未查询”，取得新房间结果后再展示电量；不沿用上个房间的卡片数值或提醒状态。

在后勤“房间用量”中查询日用量，保存后生成折线图。默认展示上海时间今天之前的 7 个完整自然日，避免把当天未结算的用量视为全天；缺失日期留空、曲线断开，真实的 0 保留。余额和用量必须属于同一房间；各自保留保存时间。学校原用量表仅标“日期/用量”，没有标明单位，当前图表明确按原站数值展示；不擅自用余额差或截图电价推算消费金额、日用量。

原站的房间选择是否还会修改服务器端绑定，需要在 M0 中确认。应用不能把修改远端绑定伪装成纯本地偏好。

### 自动记账

本人开启通知访问 → 接收支付应用通知 → 筛除无关、汇总和无法识别内容 → 明确的单笔已完成消费可自动入账 → 字段或类型有歧义时进入待确认 → 用户可修正分类、金额、时间和是否计入消费。

系统可能交付支付应用的其他通知；只处理明确识别出的支付信息，其余不保存。账本首页显示“已记录支出”，不声称通知覆盖了全部消费。

### 备份与恢复

账本 → 导出 → 用户选择保存位置 → 生成带格式版本及记录 ID 的自有 CSV。恢复时先预览新增/重复/无效行，确认后导入；不清空现有账本。明确说明导出文件包含消费信息。

## 5. 业务规则

- 课表支持星期一至星期日，不连续周次、分段单双周、连堂、同格多门课、实践周及无固定时间课程。
- 原始课表与手动修正分开保存。同步时提示冲突，不静默覆盖用户修正。
- 教学周以核对后的第 1 教学周周一为锚点；未核对时可看周课表，不显示确定的“下一节课”或启用时间提醒。
- 正式上课日与第 1 周周一可以不同。官方校历中 2027 年春季于 2 月 23 日开始上课，周次表第 1 周则从 2 月 22 日周一开始；不能把星期二当作周次锚点。
- 节次起止时间必须有校方来源或本人确认；不能按其他学校作息推测。节次配置可按学期调整。
- 已经包含补课、调课的源课表不能再自动套一遍节假日调休，避免重复移动课程。
- 无考试记录显示“当前查询暂无记录”；登录失败、读取失败不显示为“无考试”。
- 成绩保留数字、等级或其他原始表达。不自行计算学校未明确口径的总 GPA，不将补考/重修记录随意合并。
- 校历按学年管理；首版保证原版可看和离线保存。自动提取假期及考试周不是首版交付前提；采用人工核对的日期配置。
- 电量保留来源精度；空白不是 0 度，未知不是充足。首页不按截图电价换算金额，不由单次余量推测可用天数。
- 金额和电量、查询时间和业务发生时间分别处理；金额采用人民币分，显示元。
- 退款、收款、充值、转账分别标识；无法确定是否为实际消费时由用户确认统计归属。

## 6. 建议默认值

以下均为后续产品默认建议，不是已测得的限制或学校要求。0.1.1 的实际策略为：自动更新默认关闭，开启后回到应用时检查距上次成功满 30 分钟的数据，后台约每 6 小时尝试；仅自动更新各来源最近保存的查询身份。后勤需要补授权或选房时保留旧记录。

| 项目 | 建议默认 |
| --- | --- |
| 课表刷新 | 打开模块时，距上次成功同步满 24 小时尝试更新；始终可手动刷新 |
| 考试/成绩刷新 | 打开模块时，距上次成功查询满 6 小时尝试更新；始终可手动刷新 |
| 电量刷新 | 打开模块时，距上次成功查询满 30 分钟尝试更新；始终可手动刷新 |
| 后台电量查询 | 仅在 M0 验证可脱离页面读取后，提供约每 6 小时一次的可选任务；默认关闭 |
| 课程提醒 | 用户开启后，建议提前 10 分钟；教学周和节次未确认时不开启 |
| 考试提醒 | 用户开启后，建议提前 1 天及 1 小时；缺少有效时间时不安排 |
| 低电量阈值 | 绑定后由用户设置；可提供 20 度作为可调整建议值，用户开启后生效 |
| 重复低电量提醒 | 同房间首次低于阈值时提醒；仍持续偏低不重复轰炸；新有效查询恢复到阈值或以上后重置 |

后台查询时间受系统调度、网络和登录状态影响。低电量提醒只说明已查询到的状态，不能保证断电前一定通知。

## 7. 首版范围以外

桌面组件、用电预测与长期趋势分析、费用分摊、图书馆、一般通知订阅、第三方账单通用导入、自动充值或选课、云端账号、多设备同步和面向公众的多用户服务均单独排期。公开源码和个人验证安装包已由用户另行授权，近 7 天日用量图已纳入当前要求。
