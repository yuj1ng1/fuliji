## 2. M0：先验证关键接入条件

M0 也是实际开发的一部分。方案完成后用户已确认继续，接下来在同一个应用工程中验证并保留可复用实现。

| 任务 | 内容 | 通过证据 | 不通过时的处理 |
| --- | --- | --- | --- |
| M0-A 构建和设备 | 核对官方 Android Studio/SDK/JDK 组合；生成最小应用并在指定手机安装 | 固定版本记录、成功构建日志、包版本、手机可打开 | 先修复环境，不同时展开全部 UI；如需安装，优先规划到 D 盘明确独立目录，并保留现有安装 |
| M0-B 教务连接 | 本人在安卓内完成 WebVPN 与学校认证；读取当前课表，重开应用检查会话 | 真机课表字段与原站一致；明确登录失效提示 | 记录失败环节；不复制桌面凭据或冒充同步成功；评估替代方式需重新确认范围 |
| M0-C 电量 | 本人在安卓连接后勤；选择房间；读出房间和电量；核实选择动作语义 | 与原站同房间同次查询一致；换房间不串数据；只读查询路径明确 | 保留原站入口，标记自动展示未通过；不以猜测接口继续堆代码 |
| M0-D 通知 | 用户启用通知访问，验证微信/支付宝实际可交付的支付字段 | 脱敏样例、系统状态、锁屏/后台表现、识别范围与缺口 | 单一来源失败不声称另一来源也失败；手动账本可继续，自动识别能力单列 |
| M0-E 考试与成绩 | 核实查询参数、分页、非空样本及缺失字段；区分登录与空结果 | 各模块有来源字段对应表、完整性判断和非空结果核对 | 未到考试公布时间时保留该验证缺口；不伪造考试或发布成绩 |
| M0-F 时间与校历 | 使用已核对的官方 PDF 与周次表；补足节次时间，核对当前账号适用学期 | 可追溯来源或本人确认记录；无猜测日期 | 周视图可开发；节次缺失时准时提醒暂不验收 |

不为采集记账样本自动发起消费或退款。开发时的合成样例与真实通知证据明确分开；合成样例通过不能当作真机自动记账通过。

M0-B、M0-C、M0-D 分别给出结论。某一来源不支持既定方案时及时说明范围和可用替代；不能自动把“原网页可打开”降格当作“原生信息展示已交付”。独立本地功能可继续。

## 3. 开发顺序与每阶段产物

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| M0 接入验证 | 上述验证、工具链、数据字段与能力报告 | 先取得关键路径证据，再确定各功能同步方式 |
| M1 本地基础与课表 | 四个主入口、本地数据库、状态展示、学期/节次配置、课表规则、手动账本 | 合成数据醒目标记；离线可用；复杂周次与本地持久化正确 |
| M2 校园真实查询 | 课表、电量、成绩、考试接入；公开校历和离线原件 | 原站逐项核对；分页完整；失败不覆盖有效数据；房间/学期隔离 |
| M3 个人记账 | 已通过来源的通知识别、待确认、退款、分类、统计、自有 CSV 导出导入 | 不重复记账、不误合并同额交易；用户修正不被后续通知覆盖 |
| M4 提醒与真机交付 | 课程/考试提醒、低电量提醒、权限与重启恢复、迁移和备份、签名安装包 | 指定手机场景通过；保留缺口与系统限制；安装包与版本可核对 |

M0 已完成的最小验证代码在后续正式应用中复用，不另建第二套产品。阶段划分不意味着要求所有功能同时开始。

开发前不按猜测给固定工期。M0 的认证链、后台读取与通知样本结果将决定后续工作量。

## 4. 关键验收案例

下表为计划案例，全部待开发后执行。需要真实来源的案例不能只靠模拟通过。

| 编号 | 场景与预期 | 验证类型 |
| --- | --- | --- |
| A01 | 新安装可进入首页，校园卡片显示未连接，手动记账可用；拒绝通知访问不崩溃 | 真机 |
| A02 | 安卓内本人登录后显示当前课表；重开、会话失效时行为明确；收到登录页不能报同步成功 | 真机 + 真实学校 |
| A03 | 周次 1周,5-7周(单),8-10周(双),11-15周 展开为 {1,5,7,8,10,11,12,13,14,15}；不把全表达式统一按单双过滤 | 规则测试 |
| A04 | 同格多课程、周六/周日课、跨节连堂、实践周和无固定节次课程均保留；无法识别的规则显式待复核 | 规则测试 + 原站核对 |
| A05 | 教学周或节次未确认时不生成确定的下一节课时刻；周边界、跨年和周末正确；2027-02-23 归入 2027-02-22 起的第 1 周 | 规则测试 + 真机 |
| A06 | 原课表含调课时不再次套用节假日移动；用户修正与源更新冲突可见 | 规则测试 + 原站核对 |
| A07 | 网络中断、登录失效、页面结构变化均保留旧快照与原成功时间；错误原因准确 | 集成 + 真机 |
| A08 | 尚未查询、当前条件确认无记录、部分结果、第一页结果和读取失败有不同表现；分页完成前不宣称列表完整 | 集成 + 真实学校 |
| A09 | 切换学期/房间不沿用另一查询身份的数值；同房间原站电量与本次结果一致；空白不变 0，合法 0 不算缺失 | 规则测试 + 真实学校 |
| A10 | 电量首次低于阈值提醒一次；持续偏低不重复；恢复后再跌落可重新提醒；失败不能当作恢复 | 规则测试 + 真机 |
| A11 | 学年校历原版可离线查看，保留官方来源与版本；修改学期设置不篡改原件 | 真机 + 官方原件 |
| A12 | 来源明确的支付成功进入账本；退款/收款/充值/转账及多金额歧义有正确分类或待确认 | 脱敏样例 + 真机 |
| A13 | 同一回调重复、同键通知更新不会重复入账；两笔相同金额/商户且时间相近的真实交易不会被误合并 | 规则测试 + 样例 |
| A14 | 部分退款可关联且不抹去原消费；通知延迟时保留时间依据；用户修正不被重新识别覆盖 | 规则测试 |
| A15 | 微信普通聊天和其他应用通知不进入账本、不保存正文；日志和导出不含学校会话或密码 | 集成 + 真机 |
| A16 | Android 16 上分别检查前台、切后台、锁屏、重启后恢复；用户强制停止与普通后台分开记录 | 指定真机 |
| A17 | 精确提醒未授权时不显示“准时提醒正常”；修改/取消考试或课程会撤销旧提醒；时区/时间变化后可重建 | 真机 |
| A18 | CSV 导出再导入不重复，导入预览可发现无效行；升级应用/数据库后账本仍在；清理校园缓存不删账本 | 集成 + 真机 |
| A19 | 签名安装包能在目标手机安装/更新，版本与构建一致；正式页面不混入演示交易或虚构校园数据 | 构建 + 真机 |

允许通过有意义的规则测试快速验证解析、重复与状态转换；不为静态样式或文案创建大量镜像测试。真实连接、后台与权限行为必须用真实环境补足。

## 5. 完成交付时应提供

- 可安装的安卓包、版本、签名连续性和完整性校验值；发布密钥妥善保存在本地，不进入普通提交。
- 功能清单及每项真实验证状态，区分规则测试、模拟、真实学校、真实手机。
- 来源连接与授权步骤、数据导出/恢复说明、已知限制。
- 依赖锁定与构建说明，确保以后可以继续维护；不要把界面可点击等同于业务可用。

## 6. 下一次进入开发时的起点

先重读本目录文档和当时的工作区状态，确认用户新的开发指示；保留已有文件。按 M0-A 开始核实工具链并完成最小安装，再逐项验证 M0-B 至 M0-F。不得把本轮桌面证据写成应用测试通过。
